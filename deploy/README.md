# Установка на облачный сервер Рег.ру (и любой другой VPS)

Сайт — обычный Node.js-сервер без внешних зависимостей. Это **не статический сайт**: обычный хостинг
(PHP, «папка публикации») не подойдёт — нужен сервер, на котором работает Node.js 22.13+.
Все данные (книги, аккаунты, прогресс, закладки, выделения) лежат в одной папке, поэтому переезд =
поставить сайт на сервер + перенести одну резервную копию.

**Настройки сборки в панели хостинга не нужны:** команды сборки нет, `npm install` не требуется,
папки публикации нет. Главная страница — `public/index.html`, её отдаёт `server.js`. Всё настраивает `install.sh`.

## 0. Что понадобится

- **Сервер.** В Рег.ру: «Облачные серверы» → «Создать сервер»:
  - образ — **Ubuntu 24.04** или 22.04 (чистая система; шаблон «Node.js» не нужен — скрипт поставит нужную версию сам);
  - 1 ядро, 1–2 ГБ памяти, диск от 20 ГБ (книги занимают место — берите с запасом);
  - запишите IP сервера и пароль root (или добавьте SSH-ключ).
  - SSH-ключ проще, чем пароль: в разделе «SSH-ключи» нажмите «Добавить SSH-ключ» и вставьте **публичную** часть
    (`~/.ssh/id_ed25519.pub`). Ключи добавляются только при создании сервера; на уже созданном пустом сервере —
    «Ещё» → «Переустановить образ» → выбрать ключ (данные на сервере при этом стираются, IP сохраняется).
- **Домен** (желательно). Без домена нет HTTPS, а без HTTPS не работает скачивание книг и чтение без интернета.
  У домена создайте **A-запись** на IP сервера (если домен в Рег.ру — в управлении DNS-зоной домена;
  иногда запись применяется до часа).
- **Доступ к коду.** Репозиторий [Mujahhid/moy-sait](https://github.com/Mujahhid/moy-sait) публичный — токен не нужен.

## 1. Резервная копия со старого сайта (если он был)

1. Войдите на старый сайт админом.
2. «Профиль» → «Управление библиотекой» → внизу **«Скачать копию»**. Получите файл `maktabatul-backup-ГГГГ-ММ-ДД.tar`.
   Это одна архивная копия всего: база и все PDF с обложками.

Новый сайт с нуля — пропустите этот шаг и шаг 3.

## 2. Установка на сервер

Подключитесь к серверу: в панели Рег.ру у сервера есть веб-консоль, либо из терминала `ssh root@IP_СЕРВЕРА`.
Дальше три команды (подставьте свой домен):

```bash
apt-get update && apt-get install -y git
git clone https://github.com/Mujahhid/moy-sait.git /opt/kutubul
bash /opt/kutubul/deploy/install.sh library.example.ru
```

- Домен с www и без — передайте оба одной строкой в кавычках:
  `bash /opt/kutubul/deploy/install.sh 'example.ru, www.example.ru'`. Сертификат для каждого имени выпускается,
  как только его A-запись указывает на сервер (Caddy сам повторяет попытки).
- Нет домена — запускайте `bash /opt/kutubul/deploy/install.sh` без аргумента: сайт откроется по `http://IP`.
- Скрипт ставит Node.js 22, веб-сервер Caddy (сам получает HTTPS-сертификат), создаёт службу `kutubul` с автозапуском.
  Его можно запускать повторно — данные и настройки не затираются.
- Если репозиторий станет приватным, в `git clone` нужен токен только для чтения:
  `https://x-access-token:ВАШ_ТОКЕН@github.com/Mujahhid/moy-sait.git`
  (GitHub → Settings → Developer settings → Fine-grained tokens: Repository access = только этот репозиторий,
  Permissions → Contents = *Read-only*).

## 3. Перенос данных

1. Откройте новый сайт и зарегистрируйтесь (первый пользователь станет администратором).
2. «Профиль» → «Управление библиотекой» → **«Восстановить из копии»** → выберите скачанный `.tar`.
3. Сайт сам перезапустится (до минуты) и страница обновится. Войдите **своим прежним ником и паролем** —
   тот, что вы создали в п. 1, исчезнет: данные полностью заменены копией.
4. Проверьте: книги открываются, закладки и прогресс на месте.

Прежние данные нового сервера на всякий случай лежат в `/var/lib/kutubul/before-restore` — после проверки их можно удалить.

## 4. Переключение домена

Если домен раньше смотрел на старый хостинг — перенаправьте A-запись на IP нового сервера. Читателям придётся один раз войти заново
(сессия привязана к адресу сайта), сами аккаунты и всё остальное сохранятся. Старый хостинг не удаляйте, пока не убедитесь, что всё работает.

## Повседневное

| Что | Команда / место |
|-----|-----------------|
| Обновить сайт после изменений в GitHub | `bash /opt/kutubul/deploy/update.sh` |
| Посмотреть журнал | `journalctl -u kutubul -f` |
| Перезапустить | `systemctl restart kutubul` |
| Настройки (размер книги, закрыть регистрацию, ник админа) | `nano /etc/kutubul.env`, затем `systemctl restart kutubul` |
| Данные | `/var/lib/kutubul` (база `library.db`, книги в `uploads/`) |

## Резервные копии

- **Автоматически:** раз в сутки сервер сохраняет копию базы (аккаунты, прогресс, закладки) в `/var/lib/kutubul/backups`, хранится 7 штук.
  Отключить: `AUTO_BACKUP=0` в `/etc/kutubul.env`.
- PDF автокопией **не дублируются**. Раз в неделю-две скачивайте полную копию в админке («Скачать копию»)
  и/или включите платные резервные копии (снимки) сервера у хостера.
## Защита сервера

Убедитесь, что вход по SSH-ключу работает, затем отключите вход по паролю и включите брандмауэр:

```bash
printf 'PasswordAuthentication no\nKbdInteractiveAuthentication no\nPermitRootLogin prohibit-password\n' > /etc/ssh/sshd_config.d/00-keys-only.conf
sshd -t && systemctl reload ssh
ufw allow OpenSSH && ufw allow 80/tcp && ufw allow 443/tcp && ufw allow 443/udp && ufw --force enable
```

Сайт (порт 3000) слушает только `127.0.0.1` и снаружи недоступен — наружу его отдаёт Caddy по HTTPS.
Если ключ потерян, на сервер можно зайти через «Открыть консоль» в панели Рег.облака.
