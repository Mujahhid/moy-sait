# Переезд на свой сервер (Timeweb Cloud и любой другой VPS)

Сайт — обычный Node.js-сервер без внешних зависимостей. Все данные (книги, аккаунты, прогресс,
закладки, выделения) лежат в одной папке, поэтому переезд = поставить сайт на сервер + перенести одну резервную копию.

## 0. Что понадобится

- **Сервер:** Ubuntu 22.04 или 24.04, 1 ядро, 1–2 ГБ памяти, диск от 20 ГБ (книги занимают место — берите с запасом).
  В Timeweb Cloud: «Облачные серверы» → «Создать» → образ Ubuntu → запишите IP и пароль root.
- **Домен** (желательно). Без домена нет HTTPS, а без HTTPS не работает скачивание книг и чтение без интернета.
  У домена создайте **A-запись** на IP сервера (иногда она применяется до часа).
- **Доступ к коду.** Репозиторий сейчас приватный — серверу нужен токен только для чтения
  (GitHub → Settings → Developer settings → Fine-grained tokens → Generate: Repository access = только этот репозиторий,
  Permissions → Contents = *Read-only*). Или временно сделайте репозиторий публичным и токен не нужен.

## 1. Резервная копия со старого сайта (Railway)

1. Дождитесь, пока Railway задеплоит последнюю версию, и войдите админом.
2. «Профиль» → «Управление библиотекой» → внизу **«Скачать копию»**. Получите файл `kutubul-backup-ГГГГ-ММ-ДД.tar`.
   Это одна архивная копия всего: база и все PDF с обложками.

## 2. Установка на сервер

Подключитесь к серверу: в панели Timeweb есть кнопка «Консоль», либо из терминала `ssh root@IP_СЕРВЕРА`.
Дальше три команды (подставьте токен и домен):

```bash
apt-get update && apt-get install -y git
git clone https://x-access-token:ВАШ_ТОКЕН@github.com/Mujahhid/kutubul-ulum2.git /opt/kutubul
bash /opt/kutubul/deploy/install.sh library.example.ru
```

- Репозиторий публичный — в `git clone` просто `https://github.com/Mujahhid/kutubul-ulum2.git` без токена.
- Нет домена — запускайте `bash /opt/kutubul/deploy/install.sh` без аргумента: сайт откроется по `http://IP`.
- Скрипт ставит Node.js 22, веб-сервер Caddy (сам получает HTTPS-сертификат), создаёт службу `kutubul` с автозапуском.
  Его можно запускать повторно — данные и настройки не затираются.

## 3. Перенос данных

1. Откройте новый сайт и зарегистрируйтесь (первый пользователь станет администратором).
2. «Профиль» → «Управление библиотекой» → **«Восстановить из копии»** → выберите скачанный `.tar`.
3. Сайт сам перезапустится (до минуты) и страница обновится. Войдите **своим прежним ником и паролем** —
   тот, что вы создали в п. 1, исчезнет: данные полностью заменены копией.
4. Проверьте: книги открываются, закладки и прогресс на месте.

Прежние данные нового сервера на всякий случай лежат в `/var/lib/kutubul/before-restore` — после проверки их можно удалить.

## 4. Переключение домена

Если домен раньше смотрел на Railway — перенаправьте A-запись на IP нового сервера. Читателям придётся один раз войти заново
(сессия привязана к адресу сайта), сами аккаунты и всё остальное сохранятся. Railway не удаляйте, пока не убедитесь, что всё работает.

## Повседневное

| Что | Команда / место |
|-----|-----------------|
| Обновить сайт после изменений в GitHub | `bash /opt/kutubul/deploy/update.sh` |
| Посмотреть журнал | `journalctl -u kutubul -f` |
| Перезапустить | `systemctl restart kutubul` |
| Настройки (размер книги, закрыть регистрацию, ник админа) | `nano /etc/kutubul.env`, затем `systemctl restart kutubul` |
| Данные | `/var/lib/kutubul` (база `library.db`, книги в `uploads/`) |

## Резервные копии

- **Автоматически:** раз в сутки сервер сохраняет копию базы (аккаунты, прогресс, закладки) в `/var/lib/kutubul/backups`, хранится 7 штук.
  Отключить: `AUTO_BACKUP=0` в `/etc/kutubul.env`.
- PDF автокопией **не дублируются**. Раз в неделю-две скачивайте полную копию в админке («Скачать копию»)
  и/или включите платные резервные копии (снимки) сервера у хостера.
- Сервер лучше защитить: войти по SSH-ключу вместо пароля и включить брандмауэр (`ufw allow OpenSSH && ufw enable`; скрипт сам откроет 80 и 443).
